What is an AI Agent?

My understanding while learning AI Agents from scratch

Learning note: This page documents my understanding of AI agents while studying Build an AI Agent (From Scratch).

1. What am I trying to understand?

When I first heard the term AI Agent, I wondered:

What actually makes an AI system an agent?

Is an agent simply an LLM such as ChatGPT? Or does something else need to be added?

The idea that started making sense to me is:

2. The basic idea

LLM + Tools + Loop = AI Agent

An LLM can generate an answer, but an agent can use the LLM as part of a larger control loop.

The LLM can help decide:

  • What should I do next?
  • Which tool should I use?
  • What information do I need?
  • Should I continue?
  • When should I stop?

3. Three important building blocks

3.1 LLM — The decision-making core

The Large Language Model provides the reasoning and decision-making capability.

Think of it as the brain of the system.

3.2 Tools — The ability to act

Tools allow the system to interact with the outside world.

Examples:

  • Search the web
  • Call an API
  • Read a file
  • Write a file
  • Execute code
  • Query a database

3.3 Loop — The ability to continue

The loop is what makes the process more dynamic.

Evaluate context ↓
Choose an action ↓
Use a tool ↓
Get the result ↓
Add result to context ↓
Decide whether to continue ↓
Repeat or stop

4. Simple example: Research Agent

Imagine asking an AI:

"Research the latest developments in AI agents and summarize the important findings."

A traditional program might have a fixed sequence:

Search → Read → Summarize → Finish

An agent can dynamically decide what to do next.

Search source A
↓
Read result
↓
"I need more information"
↓
Search source B
↓
Compare information
↓
"I have enough information"
↓
Write summary

5. Workflow vs Agent

This was one of the most important concepts for me.

Workflow

The developer defines the execution flow.

Example:

Step 1 → Step 2 → Step 3 → Step 4

Even if an LLM is involved, the overall path is predetermined.

Agent

The LLM gets more control over the execution flow.

The model can determine:

  • Which action to take
  • Which tool to use
  • What to do next
  • Whether another step is required
  • When to stop

Simple way I remember it

Workflow: Developer controls the path.

Agent: LLM has control over more of the path.

6. Can we combine workflows and agents?

Yes.

A real application does not necessarily need to be completely workflow-based or completely agent-based.

Workflow → Agent → Workflow

A developer-defined system can contain an agent inside one of its steps.

This can help keep complex systems more controlled, predictable, and easier to debug.

7. Do we always need an agent?

No.

One important lesson is that using an agent adds complexity.

Before building an agent, ask:

  1. Does this task need an LLM?
  2. If it needs an LLM, does it actually need an agent?

If the process is predictable, a normal workflow may be simpler and more reliable.

Agents become more useful when the number and order of steps cannot easily be predicted in advance.

8. GAIA

GAIA is a benchmark used to evaluate AI agents on real-world questions that require multiple capabilities.

The important idea for me is that building an agent is not just about making it work once.

We also need to evaluate how well it performs.

9. Context Engineering

Another important concept is context engineering.

Context is more than just the prompt.

It can include:

  • System instructions
  • User messages
  • Conversation history
  • Tool results
  • Retrieved documents
  • Other information needed by the agent

Why does context matter?

An agent can fail even when the LLM itself is capable.

Sometimes the problem is that the model did not receive the right information at the right time.

Five context engineering strategies

  1. Generate
  2. Retrieve
  3. Write
  4. Reduce
  5. Isolate

10. Harness

Another concept I came across is the idea of an agent harness.

The harness is the surrounding system that helps the model operate.

It can include things such as:

  • Tools
  • Memory
  • Context management
  • Skills
  • Safe execution
  • Files and user environment
  • Evaluation and other supporting components
Agent = Model + Harness

11. My key takeaways

  1. An LLM by itself is not necessarily an agent.
  2. Tools give the system the ability to interact with the outside world.
  3. A loop allows the system to perform multiple steps and decide whether to continue.
  4. Workflows have developer-defined execution paths.
  5. Agents allow the LLM to dynamically influence the execution path.
  6. Not every problem needs an agent.
  7. Context is a critical part of building reliable agents.
  8. Understanding the internals makes agents easier to debug and improve.
